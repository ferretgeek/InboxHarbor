# 安全与隐私模型

## 保护目标

- 不让邮箱、client ID、refresh/access token、邮件、验证码或远程访问密钥落盘、进入 URL、应用日志、公开错误、截图与测试。
- 不让用户输入决定 OAuth/IMAP 主机，避免把凭据送往恶意服务。
- 避免大文件、无限账号、无限并发、长超时和无差别重试造成内存、带宽、账号锁定或服务拒绝。
- 让服务器部署默认具备明确的访问边界，而不是把私人收件接口裸露公网。

## 已实施控制

- 固定 `login.microsoftonline.com` 与 `outlook.office365.com:993`；强制 TLS 1.2+ 与系统 CA 校验。
- 只接受 OAuth2 refresh token，使用 SASL XOAUTH2；密码字段在前后端均不存在。
- 后端不记录 HTTP 请求，OAuth 原始响应和 IMAP 服务器文本不回显。
- 账号、字段长度、tenant、请求体、每批账号、并发、超时、邮件数与单封大小都有上限。
- IMAP 以只读方式打开 `INBOX`，只取最近 UID，并使用 partial fetch 限制正文大小。
- 同源检查、Host 白名单、DNS rebinding 防护、CSP、frame 禁止、Referrer/Permissions Policy 与速率限制。
- 非回环监听要求至少 32 字符访问密钥；比较使用恒定时间函数。
- 前端只以 `textContent` 渲染邮件，不把邮件当 HTML；发出请求后立即清空账号输入。
- 账号默认脱敏，邮件内容默认模糊；JSON 只导出状态、日期与计数，不含发件人、主题、正文或验证码值。

## 有意不做

- 不提供“记住账号”或服务端凭据库。
- 不支持密码、应用密码、自定义 IMAP/POP 主机、任意 OAuth URL、远程字体、分析脚本或遥测。
- 不声称清除 Python、浏览器或操作系统内存中的所有残留；这是普通应用进程无法可靠保证的。
- 不自动替用户创建 Microsoft Entra 应用或保管长期令牌。

## 剩余风险

浏览器扩展、键盘记录器、恶意系统、代理日志、屏幕录制、交换分区、崩溃转储与被接管的 Microsoft 账号仍可能读取敏感内容。验证码提取是启发式结果，用户必须自行核对。远程访问时，访问密钥不能替代 HTTPS。
